# 生成式广告 Demo 方案（面试用）

> 目标：用一个能跑、能操作的 demo，让面试官在**动手**中看出你对"chat 原生变现"这件事的理解深度。
> 核心卖点：demo 不是展示"我会做聊天广告"，而是展示"我把**信任 vs 收入**这个抽象矛盾，抽象成了一个**可拨动、可解释的模型**"——正好命中 JD 要求"把复杂问题抽象为可执行的标准"。

---

## 一、总纲（开场定调的一句话）

> "信息流广告的载体和广告是两个东西拼在一起；chat 广告的载体和广告是同一句话。这个根本差异决定了：传统广告靠'把打断做得不烦'，chat 广告靠'让商业信息从信任里自然长出来'。所以我的设计不是'怎么插广告'，而是'怎么在不消耗信任的前提下完成一次商业连接'。"

---

## 二、产品骨架：一条流水线（体现系统思维）

四块不是四个独立页面，而是一条消息流过的六个工位——这本身就是真实系统的样子：

```
用户消息
  │
  ▼
① 意图识别    → {强度:0.87, 层级:强商业, 品类:手机}
  │
  ▼
② 触发闸门    → 阈值线(受"激进度"滑块控制) → 判定:触发/软引导/不触发
  │
  ▼
③ 语义竞价    → 候选广告主在意图空间竞价，排序 = 匹配×出价×体验分 → 中选
  │
  ▼
④ 渲染回答    → 文本 + (可选)商品卡
  │
  ▼
⑤ 指标结算    → 收入指标↑ + 护栏指标(按累积决策非线性演化)
  │
  ▼
⑥ eval评分    → 四维打分 + LLM-Judge 裁决(实时给这轮对话打分)
```

## 三、灵魂：信任损耗模型（demo 里最值钱的部分）

### 要回答的问题
"在对话里插一次广告，到底'亏'了什么？"——赚的是眼前的钱，花的是用户的信任。

### 核心洞察：同样插一条广告，亏的信任天差地别（非对称）

| 用户意图 | 赚的钱 | 亏的信任 | 理由 |
|---|---|---|---|
| 强商业（想买手机） | 高 | 几乎为0 | 用户本来就想买，你帮了他 |
| 弱商业（问护理） | 中 | 中 | 有点打扰，但还能接受 |
| **纯信息/情感（emo）** | 低 | **极高** | 用户在托付信任，你恰饭=**信任连带损伤**，污染前后所有回答的信任 |

### 两个关键性质
- **非对称**：同样动作，纯情感场景亏的信任是强商业的几十倍。
- **非线性（平方项）**：越是不该插广告的地方硬插，损伤不是"多一点"而是"暴增"。用平方项表达"越错越离谱"。

### 模型算式（可解释的假设，非真实数据）
```
信任损耗 = 触发强度 × 意图错配度²
```
- 平方项体现纯信息场景恰饭的"连带损伤"。
- **坦诚它是假设模型**：面板露出说明——"真实系统里这个函数要靠 A/B 实验的留存差来拟合"。被追问"数据哪来的"时，把追问变成主场："这正是我想聊的——真实系统怎么标定它。"

### 滑块与模型的关系
"激进度"滑块 = **你有多贪** = **下调触发阈值**。
- 往克制拉：只在强商业才触发。赚少，信任几乎不亏。
- 往激进拉：弱意图、纯情感也开始触发。收入短期涨，但按上表信任**非线性暴亏** → 护栏指标越过某点**突然崩塌**。
- **那个突然崩塌的点 = 红线**。demo 让面试官亲手拖出它。

### 大白话总结
> "在对话里插广告，赚的是眼前的钱，花的是用户的信任。用户越是没想买、越是在跟你掏心窝子的时候，你插广告，花掉的信任就越多——多到不成比例。这个模型把'花掉多少信任'变成一个能算、能拨、能看的数字。"

## 四、eval 评测（Step4）

### 作用
前三步决定"AI 这轮**做了什么**"，eval 回答"AI 这轮**做得好不好**"。每轮实时打分：

> 本轮评分：相关性 4/5 · 有用性 5/5 · 露出恰当性 2/5 ⚠ · 信任伤害 高 ⚠
> 裁判点评：用户是纯情感倾诉，此处插入鲜花广告属错配触发，严重损害信任，建议不予露出。

四个维度：**相关性 / 有用性 / 露出恰当性 / 信任伤害**。方法：**硬断言 + LLM-as-Judge 双轨**（直接对上你小米虾米平台经历）。

### 实现：预设为主 + 真实兵备
- 预设场景 → 预设裁决（演示丝滑、离线、稳定）。
- 真实输入模式 → 才真调 API。
- **加分话术**："预设+真实双轨反映了 LLM-Judge 的真实工程问题：纯 LLM 裁判不稳定、有偏见、一致性要靠人工标注校准，所以真实系统要硬断言兜底 + LLM-Judge 补软性判断——这正是我在小米做的。"

## 五、竞价机制（第三幕核心）

### 核心问题
用户问"3000块打游戏手机"，一堆厂商都想被推、都交了钱。只能推一个，推谁？传统搜索广告=价高者得，但 chat 这么干会灾难（推了不搭的商务机 / 话术恶心的广告主）。

### 排序公式（三项相乘）
```
最终得分 = 意图匹配度 × 出价 × 体验分
```
- **① 意图匹配度**：推的东西是不是用户真想要的（有用性守门员）。
- **② 出价**：平台的收入来源（商业价值）。
- **③ 体验分**：话术/口碑会不会恶心用户——**把信任保护焊进竞价的地方**。

### 第三幕让面试官操作（拖动某广告主出价）
- **啊哈1（光有钱没用）**：把不匹配的商务机出价拉到最高，因匹配度只 0.4，总分仍排不上 → 匹配度是硬门槛，钱买不到推荐位。
- **啊哈2（话术恶心也没用）**：把体验分低的广告主出价拉高，低体验分压下总分 → 信任保护内建在排序里，不靠事后审核。

### 追问武装："为什么相乘不是加权求和？"
> "相乘是**否决式**设计——任何一项接近0，总分接近0。匹配度极低或体验分极低的广告主，**不管出价多高都该被毙**，而不是靠高出价把低匹配'赎买'回来。加权求和做不到否决，会让钱把体验赎买回来。相乘天然实现'木桶短板一票否决'，和我 Step1 的'护栏一票否决'是同一哲学。"

## 六、叙事路径（发链接自己玩 → 内置引导浮层）

面试官打开点"▶ 开始引导演示"，三幕逐步提示。

### 第一幕——"AI 是有分寸的"（对应 Step2 意图分层）
- 引导发强商业："推荐个3000块能打游戏的手机" → 回答+商品卡，面板"强商业 0.87，触发"。
- 引导发纯情感："我今天好emo，想找人聊聊" → 只给情感回应，面板"纯情感 0.05，克制不触发"。
- **啊哈**：同一系统，一个插广告一个忍住了 → 意图分层是真判断。

### 第二幕——"贪婪是有代价的"（对应 Step1 信任约束，杀手锏）
- 引导把激进度滑块从克制拖到激进。
- 收入缓涨 → 越过某点，护栏指标（次留/负反馈/主动关闭率）接连变红破线闪烁 → emo 场景也开始弹鲜花广告。
- **啊哈**：面试官**亲手**拖出"收入涨一点、信任崩一片"（全场最高光 30 秒）。

### 第三幕——"背后有一套可解释的机器"（对应 Step3 竞价 + Step4 eval）
- 同一 query 下调某商家出价，看排序怎么变（匹配×出价×体验分），看高出价低体验商家排不上；看 eval 裁判打分。
- **啊哈**：不是随机弹广告，是有排序逻辑、有质量评判、信任保护焊进机制的系统。

## 七、技术方案

- **技术栈**：React + Vite + TypeScript + Tailwind CSS。图表 Recharts 或轻量手写。状态 Zustand。
- **意图引擎可插拔**（`IntentEngine` 接口，一个开关切换）：
  - `PresetEngine`：规则+预存值，离线零依赖，断网也能演。
  - `LLMEngine`：填 API key 走真实模型，接真实 query 输入框。
  - **"可插拔"本身也是给面试官看的**：证明懂工程抽象。
- **数据层**：
  - `scenarios.ts`：预设典型 query（强/弱/无商业各若干）——"评测数据集"缩影。
  - `advertisers.ts`：模拟商家库（出价/品类/话术质量）。
- **部署**：GitHub Pages / Vercel 一键，拿分享链接。

### 主场景品类
- **手机**（标品，商品卡形态，轻）
- **医美或装修**（高客单、决策链长，导购 Agent 形态，重）
- 两个品类正好演示 Step3 说的"从轻形态到重形态"。

## 八、范围红线（坚决不做，防止越做越大）

**砍掉**：用户账号、真实支付、真实商家数据库、对话历史持久化、多语言。
demo = **单页、单会话、刷新即重置**。

## 九、构建顺序（每步都是可演示版本）

1. **脊椎**：三栏布局 + 顶部滑块 + 流水线数据流跑通（工位先出假数据）。能发消息、拖滑块、指标能动 = MVP。
2. **加深②意图分层触发**：意图强度可视化、三层判定、阈值线可拖。
3. **加深①信任护栏滑块**：信任损耗模型接入、护栏红线破线动画（杀手锏）。
4. **加深③语义竞价**：候选卡片展示 匹配×出价×体验分 排序过程。
5. **加深④eval**：实时四维打分 + LLM-Judge 裁决卡。
6. **收尾**：接 `LLMEngine` 真实输入兵备 + 引导浮层 + 部署。
