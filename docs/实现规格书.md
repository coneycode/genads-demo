## 0. 一句话产品定义

一个可交互的单页 Web Demo，模拟"AI 对话中如何在**不消耗用户信任**的前提下插入商业信息"。用户（面试官）通过发消息、拖动"变现激进度"滑块、调整广告主出价，**亲眼看到收入与信任的实时权衡**。

## 1. 技术栈与工程约束

- **框架**：React 18 + Vite + TypeScript
- **样式**：Tailwind CSS
- **状态管理**：Zustand（单一 store）
- **图表**：Recharts（仪表盘折线/条形）
- **图标**：lucide-react
- **部署目标**：GitHub Pages / Vercel（纯静态，`vite build` 产物可直接托管）

  - 默认离线可跑（不依赖任何网络请求）。真实 LLM 为可选增强，需用户填 API Key。
  - 所有中文文案直接写死在代码/数据文件中。

## 3. 核心类型定义（`engine/types.ts`）

```typescript
// 意图层级
export type IntentLayer = 'strong' | 'weak' | 'none';
// strong=强商业, weak=弱商业, none=纯信息/情感

// 品类
export type Category = 'phone' | 'renovation' | 'none';
// phone=手机(标品/轻形态), renovation=装修(高客单/重形态导购)

// 意图识别结果
export interface IntentResult {
  strength: number;        // 0~1，商业意图强度
  layer: IntentLayer;      // 由 strength 映射
  category: Category;      // 命中的商业品类
  reason: string;          // 一句话解释（面板展示，也用于面试讲解）
}

// 广告主/商家
export interface Advertiser {
  id: string;
  name: string;
  category: Category;
  matchKeywords: string[]; // 用于计算与 query 的匹配度（Preset 模式）
  baseMatch: number;       // 0~1，与本品类核心意图的基础匹配度
  bid: number;             // 出价（元），可被用户在竞价面板调整
  experience: number;      // 0~1，体验分（话术/口碑质量）
  copyStyle: 'natural' | 'hard'; // 话术风格：自然 / 硬广
  adText: string;          // 广告露出时的文案
  product: ProductInfo;    // 用于渲染商品卡
}

export interface ProductInfo {
  title: string;
  subtitle: string;
  price: string;
  tags: string[];
  imageEmoji: string;      // 用 emoji 占位，避免图片资源依赖
}

// 竞价候选（排序后）
export interface BidCandidate {
  advertiser: Advertiser;
  matchScore: number;      // 意图匹配度 0~1
  bid: number;
  experience: number;
  finalScore: number;      // = matchScore × bid × experience
  won: boolean;            // 是否中选
}

// 触发闸门判定
export type GateDecision = 'trigger' | 'soft' | 'none';
// trigger=触发露出(商品卡), soft=软引导(结尾一句非侵入提示), none=不触发

// eval 四维打分
export interface EvalScore {
  relevance: number;       // 相关性 1~5
  usefulness: number;      // 有用性 1~5
  appropriateness: number; // 露出恰当性 1~5
  trustHarm: 'low' | 'mid' | 'high'; // 信任伤害
  verdict: string;         // 裁判点评（一句话）
}

// 指标快照
export interface Metrics {
  // 收入侧
  exposureRate: number;    // 商业露出率 %
  clickRate: number;       // 点击/线索率 %
  revenue: number;         // 累计收入（元，模拟）
  // 护栏侧（信任）
  retention: number;       // 次日留存 %
  negativeFeedback: number;// 负反馈率 %
  activeClose: number;     // 主动关闭商业化率 %
}

// 一轮对话的完整记录（贯穿流水线）
export interface Turn {
  userText: string;
  intent: IntentResult;
  gate: GateDecision;
  candidates: BidCandidate[];   // 竞价结果（空=未触发）
  winner: Advertiser | null;
  aiText: string;               // AI 回答正文
  showCard: boolean;            // 是否渲染商品卡
  trustCost: number;            // 本轮信任损耗
  eval: EvalScore;
}
```

## 4. 意图层级映射（固定规则）

```
strength >= 0.7            → layer = 'strong'  (强商业)
0.3 <= strength < 0.7      → layer = 'weak'    (弱商业)
strength < 0.3             → layer = 'none'    (纯信息/情感)
```

## 5. 信任损耗模型（`engine/trustModel.ts`）—— DEMO 的灵魂

### 5.1 变现激进度滑块 → 触发阈值
滑块值 `aggressiveness ∈ [0, 1]`（0=克制，1=激进）。触发阈值：
```
threshold = 0.9 - aggressiveness * 0.85
```
- aggressiveness=0 → threshold=0.90（几乎只有强商业能触发）
- aggressiveness=0.5 → threshold=0.475（弱商业也开始触发）
- aggressiveness=1 → threshold=0.05（连纯信息/情感都触发）

### 5.2 触发闸门判定
```
若 intent.strength >= threshold           → gate = 'trigger'
否则若 intent.strength >= threshold - 0.2 → gate = 'soft'   （临界区，软引导）
否则                                       → gate = 'none'
```

### 5.3 单轮信任损耗（核心公式）
仅当 `gate === 'trigger'` 或 `'soft'` 时产生损耗（`none` 时 trustCost=0）：
```
triggerIntensity = (gate === 'trigger') ? 1.0 : 0.5   // 商品卡=1.0，软引导=0.5
STRONG_BASELINE  = 0.8
mismatch = clamp((STRONG_BASELINE - intent.strength) / STRONG_BASELINE, 0, 1)
trustCost = triggerIntensity * (mismatch ** 2)          // 平方项 = 非对称/非线性
```
**数值直觉**（triggerIntensity=1.0 时）：
- 强商业 strength=0.87 → mismatch≈0 → trustCost≈0.00（几乎不亏）
- 弱商业 strength=0.50 → mismatch=0.375 → trustCost≈0.14
- 纯情感 strength=0.05 → mismatch=0.94 → trustCost≈0.88（暴亏）

### 5.4 指标演化（累积 trustCost 驱动）
维护 `cumulativeTrustCost`（累加每轮 trustCost）与 `adShownCount`、`turnCount`。

```
// 护栏指标（信任，随累积损耗劣化）
retention        = clamp(68 - 6.0 * cumulativeTrustCost, 40, 68)   // 起点68%
negativeFeedback = clamp(2  + 6.0 * cumulativeTrustCost, 2, 30)    // 起点2%
activeClose      = clamp(1  + 5.0 * cumulativeTrustCost, 1, 25)    // 起点1%

// 收入指标（随广告露出增长）
exposureRate = turnCount>0 ? (adShownCount / turnCount) * 100 : 0
clickRate    = 加权：每次 trigger +约8%，soft +约3%，取近若干轮均值（简化可用累计点击/曝光）
revenue     += winner ? winner.bid * (0.6 + 0.4 * matchScore) : 0   // 每次露出按出价×匹配折算
```

### 5.5 红线阈值（破线→变红闪烁 + "一票否决"提示）
```
retention        < 60   → 破线
negativeFeedback > 8    → 破线
activeClose      > 5    → 破线
```
任一破线时，右栏顶部显示红色横幅：
> ⚠ 护栏指标破线 —— 按"一票否决"原则，此激进度下的策略不予上线。

## 6. 竞价机制（`engine/bidding.ts`）

### 6.1 匹配度计算（Preset 模式）
```
matchScore = advertiser.baseMatch 微调：
  若 query 命中 advertiser.matchKeywords 中的词 → 在 baseMatch 基础上 +0.05/词，clamp 到 [0,1]
  品类不匹配（advertiser.category !== intent.category）→ matchScore *= 0.3
```

### 6.2 排序
```
finalScore = matchScore * bid * experience
按 finalScore 降序排序，第一名 won=true。
```
**关键：相乘而非加权求和**（否决式设计）。任一项接近 0，总分接近 0 —— 匹配差或话术恶心的高价广告主排不上。

### 6.3 露出
- `gate==='trigger'`：渲染中选广告主的商品卡（`ProductCard`）。
- `gate==='soft'`：仅在 AI 回答结尾追加一句非侵入提示（`advertiser.adText` 的柔和版，不出卡）。
- `gate==='none'`：无任何商业露出。

## 7. eval 评测（`engine/evaluator.ts`）

### 7.1 预设模式打分（离线，规则生成，保证自洽）
```
relevance       = round(1 + 4 * matchScore)            // 匹配度→相关性
usefulness      = gate==='none' ? 5 : round(3 + 2*matchScore - 2*mismatch)
appropriateness = clamp(round(5 - 5*mismatch), 1, 5)   // 错配越高越不恰当
trustHarm       = trustCost < 0.1 ? 'low' : trustCost < 0.4 ? 'mid' : 'high'
```
### 7.2 裁判点评（`verdict`）按 layer + gate 选预设模板，例如：
- strong+trigger：「用户有明确购买意图，露出相关商品卡，相关且有用，信任无损。」
- none+trigger：「用户为纯信息/情感诉求，此处插入商业卡属错配触发，严重损害信任，建议不予露出。」
- weak+soft：「用户有潜在需求，以非侵入方式软引导，权衡得当。」

### 7.3 真实模式
`LLMEngine` 开启时，用一次 API 调用让模型按上述四维输出 JSON。失败则回退预设。演示默认走预设（丝滑、稳定）。

## 8. 意图引擎（`engine/intentEngine.ts`）

### 8.1 接口
```typescript
export interface IntentEngine {
  analyze(query: string): Promise<IntentResult>;
}
```
### 8.2 PresetEngine（默认）
- 先在 `scenarios.ts` 里精确匹配 query → 直接返回预存 IntentResult。
- 未命中时用关键词规则兜底：命中手机/装修关键词按品类给中高 strength；命中情感词（emo/难过/陪我/聊聊）给极低 strength；否则给 strength=0.2, layer='none'。

### 8.3 LLMEngine（可选）
- 构造 prompt 让模型输出 `{strength, category, reason}` 的 JSON。
- API Key 由用户在 Header 的设置里填入，存于内存（不持久化）。
- 任何错误 → 回退到 PresetEngine。

### 10.1 整体（`App.tsx`）

### 10.2 Header
- 标题："生成式广告 · Chat 原生变现沙盘"
- **变现激进度滑块**（0~1，标注左"克制"右"激进"，实时显示当前 threshold）。全场核心控件，视觉突出。
- 引擎开关：`预设 | 真实LLM`（切到真实需填 API Key 的小输入）。
- 重置按钮：恢复初始 metrics 与对话。

### 10.3 ChatPanel（左）
- 消息列表（用户/AI 气泡），AI 气泡内按 `showCard` 渲染 `ProductCard`。
- 底部输入框 + 发送。
- **快捷 query 按钮区**：把 `scenarios.ts` 里的典型 query 做成一排可点击 chip（方便面试官零成本触发各场景）。

### 10.4 EnginePanel（中）—— "引擎透视"，四工位竖排
- **IntentStage**：显示 strength（进度条）、layer 徽章（强/弱/无，配色 绿/黄/灰）、category、reason。
- **GateStage**：一条 0~1 的数轴，画出当前 threshold 竖线 + 当前 query 的 strength 点；判定结果徽章（触发/软引导/不触发）。滑块变化时 threshold 线实时移动。
- **BiddingStage**：候选广告主列表，每行显示 `matchScore × bid × experience = finalScore`，中选行高亮 won。**每个候选带一个出价滑块**，用户可实时调 bid 看排序变化。gate≠trigger 时显示"本轮未触发竞价"。
- **EvalStage**：裁决卡，四维分（相关性/有用性/露出恰当性用 1~5 星或条，信任伤害用 低/中/高 徽章）+ verdict 点评文本。

### 10.5 MetricsPanel（右）—— 指标仪表盘
- 顶部：破线红色横幅（任一护栏破线时出现）。
- **收入区**：露出率、点击率、累计收入（数字 + 一条随对话增长的迷你折线）。
- **护栏区**（三个 `GuardrailMeter`）：次留、负反馈率、主动关闭率。每个条显示当前值、红线位置；**破线时变红 + 闪烁动画**。
- 视觉语言：收入=蓝/绿"油门"，护栏=遵循红线状态（正常灰绿 / 破线红）。

### 10.6 ProductCard
- 手机卡与装修卡复用同一组件，按 `ProductInfo` 渲染：emoji 图 + 标题 + 副标 + 价格 + 标签。
- 硬广风格（copyStyle==='hard'）可加一个刺眼的红色促销条，视觉上就"像恶心广告"，强化体验分低的直观感受。

## 11. 引导浮层三幕（`data/tour.ts` + `TourOverlay.tsx`）

浮层引导面试官按顺序体验，每幕一个高亮区域 + 提示文案 + "下一步"。可跳过、可重开。

**第一幕 · "AI 是有分寸的"**
1. 提示："点下面这句强商业问题" → 高亮快捷 chip「推荐个3000块能打游戏的手机」。用户点后：AI 出商品卡，中栏意图面板显示"强商业 0.87 · 触发"。
2. 提示："再点这句情感问题" → 高亮「我今天好emo，想找人聊聊」。用户点后：AI 只给情感回应，面板"纯情感 0.05 · 克制不触发"，无卡。
3. 旁白："同一个系统，一个推荐、一个忍住——这就是意图分层触发。"

**第二幕 · "贪婪是有代价的"（杀手锏）**
1. 提示："把顶部『变现激进度』滑块慢慢拖到最右" → 高亮 Header 滑块。
2. 用户拖动时：右栏收入指标上升；越过阈值后护栏指标接连变红破线闪烁；之前的情感场景重发会开始弹广告。
3. 旁白："收入涨一点，信任崩一片。护栏指标破线就一票否决——这就是 chat 变现的红线。"

**第三幕 · "背后有一套可解释的机器"**
1. 提示："发一句装修问题" → 高亮「我家90平想做全屋装修，预算15万够吗」。
2. 提示："在中栏竞价区，把『低价装修(硬广)』的出价拉到最高" → 高亮其出价滑块。用户拉高后：它因 experience=0.25 仍排不上，中选的是话术自然的优选整装。
3. 旁白："出价最高也赢不了——匹配度和体验分是硬门槛，信任保护焊在竞价里，不靠事后审核。"

## 12. 数据流（Zustand store 关键 action）

`useStore.ts` 维护：`aggressiveness`, `messages`, `currentTurn`, `metrics`, `cumulativeTrustCost`, `adShownCount`, `turnCount`, `engineMode`, `apiKey`, `advertisers`（含可变 bid）。

**核心 action：`sendMessage(text)`**（流水线）：
```
1. intent = await engine.analyze(text)
2. threshold = 0.9 - aggressiveness*0.85
3. gate = 判定(intent.strength, threshold)
4. if gate!=='none':
      candidates = rankBids(text, intent, advertisers)  // 计算并排序
      winner = candidates[0]?.advertiser
   else: candidates=[], winner=null
5. trustCost = computeTrustCost(gate, intent.strength)
6. 更新累积量与 metrics（见 §5.4）
7. aiText = 生成回答（预设模板：按品类/情感给一段自然回应；gate==='soft'追加柔和引导）
8. showCard = (gate==='trigger' && winner)
9. evalScore = evaluate(intent, gate, winner, trustCost)
10. push 到 messages，更新 currentTurn（供中栏各工位展示）
```

**`setAggressiveness(v)`**：更新滑块值；仅影响后续消息（threshold 线实时动）。可选增强：对最近一条消息重算 gate 以即时反馈。

**`setBid(advertiserId, bid)`**：更新商家出价；若当前有 currentTurn，实时重算竞价排序刷新中栏。

**`reset()`**：全部恢复初始。

## 14. 构建顺序（每步产出一个可演示版本）

7. **引导浮层三幕**（§11）。
8. **真实 LLM 兵备**（LLMEngine + API Key 输入 + 失败回退）。

## 15. 验收标准（Definition of Done）

- [ ] 离线可跑，刷新即重置，无网络依赖（预设模式）。
- [ ] 三个预设"啊哈"数据自洽：
  - 强商业问手机 → 触发商品卡，护栏不破线。
  - 纯情感问题 → 默认克制不触发；把激进度拉满后才触发，且护栏立刻破线红闪。
  - 装修问题下把"低价装修(硬广)"出价拉最高 → 仍排不过话术自然的整装（体验分否决）。
  - 手机问题下把"商务旗舰"出价拉最高 → 仍排不过 iQOO（匹配度否决）。
- [ ] 引导浮层三幕可完整走通，可跳过/重开。
- [ ] 真实 LLM 模式：填 Key 后任意 query 可实时分析；出错自动回退预设。
- [ ] 部署后有可公开访问的分享链接。
